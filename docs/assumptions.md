| A1 | 2026-08-24 | Image width/height **W is a compile-time `conv_top` parameter** (default 32 from `rtl/pkg_params.sv`); one W per bitstream. | The serpentine line buffers are fixed-length SRL delays of depth W−N; runtime W would force addressed line memories (BRAM, ×100 FoM cost) or tap-muxed max-length SRLs. Compile-time W keeps the zero-BRAM FoM strategy and the exactness of the latency formula. | A2 | 2026-08-24 | **All kernel banks are loaded before streaming starts** (before `cfg_start`); writing the active bank during PRIME/RUN/FLUSH is undefined for in-flight pixels. LOAD_KERNEL is a mandatory one-cycle configuration/arming state, not a transfer state. | Avoids shadow-register area and a load/compute arbitration path that would add LUTs and a timing arc for no FoM benefit; the arming state plus 4 banks already covers every use case including the multi-kernel bonus. | §2 Assumptions, §6 Control FSM |
| A3 | 2026-08-24 | **No padding**: borders are masked, so a W×W input yields (W−N+1)² = 900 outputs; the first N−1 rows and first N−1 columns of each row produce no output. | Padding adds mux/boundary logic and produces edge outputs of degraded validity; masking keeps the no-backpressure datapath small, while the clock-enabled pipeline holds coherently across input-valid gaps and the valid count remains provable by SVA (`a_valid_count`). Standard "valid" convolution semantics, matched exactly by the golden model. | §2 Assumptions, §4 Window generation |
| A4 | 2026-08-24 | Output scaling uses a **programmable round-half-up right shift `cfg_out_shift` (0–7)** ahead of saturation; shift 0 for integer filters, shift 7 (Q1.7 kernels) for the quantized CNN demo. The shift used is stated with every result. | A single fixed scale cannot serve both raw integer filters (Sobel, saturation tests) and INT8 CNN inference; a 3-bit config field costs almost nothing and makes the saturation policy testable at shift 0. | §2 Assumptions, §7 Fixed-point |
| A5 | 2026-08-24 | Multi-kernel runs require the host to **re-stream the identical frame once per bank** (no on-chip frame buffer). | A frame buffer would cost BRAM (×100 FoM penalty) solely to save host bandwidth; re-streaming is free in simulation and trivial over UART for the demo. | §2 Assumptions, §6 Control FSM |
| A6 | 2026-08-28 | Kernel geometry is **fixed at N=3 (3×3)**; coefficient values remain runtime-programmable in four banks. | The competition requires programmable N×N kernel coefficients but does not require N itself to be runtime- or elaboration-selectable. Fixing N preserves the nine-multiplier array, fixed three-stage tree, 20-bit exactness proof, P_PIPE=6 latency, and low-FoM-cost implementation. | §2 Assumptions, §§3–6 Architecture, §12 Tradeoffs |
| A7 | 2026-08-28 | **The golden model is generalized over N and W; the RTL is not.** `model/golden_conv.py` derives every width from closed-form functions of N (`PROD_W(N)`, `ACC_W(N)`, …) and is exercised at N=5 / W=64 to prove the width formulas, while `rtl/pkg_params.sv` keeps the fixed N=3 of [A6](#). | The width-sufficiency proof is only credible if the formulas are shown to generalize rather than being hardcoded constants that happen to be right at N=3. Generalizing the *model* costs nothing and produces that evidence; generalizing the *RTL* would make P_PIPE, the adder-tree depth, and the T_first formula variable, invalidating the frozen interface, the 9-multiplier FoM story, and every doc that cites `73` cycles — for zero FoM benefit. Resolves the conflict between the build prompt (Phases 3–4: "fully parameterized in N") and A6. | §2 Assumptions, §7 Fixed-point, §12 Tradeoffs |
| A8 | 2026-08-28 | **Reset is `rst_n`: asynchronous assert, synchronous deassert**, per [04_interfaces.md](04_interfaces.md), rather than the fully synchronous reset named in the build prompt. | The frozen interface contract in docs/04 governs; changing the reset scheme would require a coordinated RTL+TB+docs PR under CONTRIBUTING rule 3 for no measured benefit. The scheme is applied uniformly — no module mixes reset styles — and reset is not on any timing-critical path in a design with no reset-dependent fabric primitives. | §2 Assumptions, §5 RTL implementation |
| A9 | 2026-08-28 | The **real-image vector family** (`real_lena32`, `real_neu32`, `real_pcb32`) is generated only from committed source assets under `model/vectors/assets/`. Until those assets exist, `gen_vectors.py --all` **fails with an actionable error** and the family is absent; it is never substituted with synthetic data, and `--skip-real` records in the manifest that the Phase 2 gate is unmet. | A synthetic stand-in for a "real image" vector would make the suite look complete while testing nothing about realistic pixel statistics, and it would silently corrupt the SAIF power methodology ([06_implementation_flow.md](06_implementation_flow.md) §4), which requires switching activity from a real frame. Failing loudly keeps the gap visible and attributable. Provenance and the crop/resize procedure are frozen in [05_verification_plan.md](05_verification_plan.md) §2.3. | §2 Assumptions, §10 Verification |
| A10 | 2026-08-28 | The two **(W-N)-deep line-buffer delay lines in `line_window` carry no reset**; every other register in the design (the nine window taps, all MAC/tree/normalize datapath registers, the in-flight metadata pipeline, `kernel_regfile` and every `ctrl_fsm` state element) keeps `rst_n` per [04_interfaces.md](04_interfaces.md). | Resolves a conflict *between two docs*: [02_architecture.md](02_architecture.md) §2 mandates SRLC32E mapping with `(* srl_style = "srl" *)` and the [06_implementation_flow.md](06_implementation_flow.md) §1.5 build gate fails on BRAM≠0, but SRLC32E has no reset port, so a reset on the chain forces ~536 flip-flops instead of two SRLs and forfeits the zero-BRAM mapping claim — a direct FoM loss for no functional gain. Safe because border masking is positional, not data-dependent: `ctrl_fsm` qualifies an output only when `row_cnt ≥ N−1 && col_cnt ≥ N−1`, so undefined post-reset contents of the delay line can never reach a qualified output. Checked, not assumed — the testbench asserts no `out_valid` during priming and that the first qualified output follows a fully determined window. | §2 Assumptions, §5 RTL implementation, §11 Utilization |
| A11 | 2026-09-19 | **Real-image stimulus crops are native-resolution windows, never resized.** [05_verification_plan.md](05_verification_plan.md) §2.3 originally specified "centre-crop to square, resize to W×W with a box filter"; that resize step is NOT used for anything that feeds the hardware. A W×W crop is cut directly from the source at its original scale. Resizing survives only for the `*_display.png` full-scene figures, which are presentation artefacts and never stimulus. | Resizing is a low-pass filter: it averages neighbouring pixels and suppresses exactly the high-frequency content that makes adjacent pixels differ. Toggle activity on `px_data` would therefore be systematically understated, the SAIF capture would report less switching than the design really sees, dynamic power would come out optimistically low, and the FoM — the competition's headline metric — would be inflated by a measurement artefact. Native crops keep the switching statistics honest. Measured on the generated set, detail crops reach 0.46 bit-flips per input bit per pixel against 0.12 for a flat region, a spread that a box-filtered resize would have flattened. | §2 Assumptions, §7 Fixed-point, §11 Implementation results |
